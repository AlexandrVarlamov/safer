Добавить загрузку конфигурации из `.env` через `godotenv` + `caarlos0/env/v11`, с типизированной структурой в `internal/config`.

## Шаги

1. **Добавить зависимости**
   ```
   go get github.com/joho/godotenv github.com/caarlos0/env/v11
   ```

2. **Создать `internal/config/config.go`** (первый файл в пустом пакете):
   ```go
   package config

   import (
       "fmt"
       "os"

       "github.com/caarlos0/env/v11"
       "github.com/joho/godotenv"
   )

   type Config struct {
       AccountID       string `env:"ACCOUNT_ID,required"`
       APIToken        string `env:"API_TOKEN,required"`
       AccessKeyID     string `env:"ACCESS_KEY_ID,required"`
       SecretAccessKey string `env:"SECRET_ACCESS_KEY,required"`
   }

   func Load() (*Config, error) {
       // .env опционален: локально грузим из файла, в проде — реальные env-переменные.
       // godotenv.Load не перезаписывает уже существующие переменные,
       // поэтому реальное окружение всегда имеет приоритет над .env.
       if err := godotenv.Load(); err != nil && !os.IsNotExist(err) {
           return nil, fmt.Errorf("load .env: %w", err)
       }
       var cfg Config
       if err := env.Parse(&cfg); err != nil {
           return nil, fmt.Errorf("parse config: %w", err)
       }
       return &cfg, nil
   }
   ```
   Поля — ровно те 4 ключа, что уже лежат в вашем `.env` (Cloudflare R2-креды). Если конфиг будет расти, добавляются поля с тегами (`env:"PORT" envDefault:"8080"` и т.п.).

3. **Встроить в `cmd/main.go`** — конфиг грузится первым делом, при ошибке быстрый fail:
   ```go
   func main() {
       cfg, err := config.Load()
       if err != nil {
           log.Fatalf("config: %v", err)
       }
       // ...
   }
   ```

4. **Создать `.env.example`** в корне с теми же 4 ключами и плейсхолдерами (`ACCOUNT_ID=your-account-id` и т.д.) — коммитится в git как документация (`.gitignore` его не трогает, игнорируется только точное имя `.env`).

5. **Тест `internal/config/config_test.go`**: через `t.Setenv` проверить, что `Load` возвращает ошибку при отсутствующих переменных и успешно парсит, когда все заданы. Сам `.env` в тесте не трогаем.

6. **Проверка**: `go mod tidy`, `go build ./...`, `go test ./...`, затем запустить бинарник — он должен подхватить ваш существующий `.env` без ошибок (значения в вывод не печатаем).

## Принципы, которые закладываем
- `.env` — только для локальной разработки; в проде те же переменные приходят из реального окружения (12-factor).
- Приоритет: реальное окружение > `.env` (так работает `godotenv.Load`).
- Секреты не коммитятся: `.env` уже в `.gitignore`, в git лежит только `.env.example`.
